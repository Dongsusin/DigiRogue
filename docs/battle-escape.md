# 도망과 스테이지 전환

일반 전투에서 도망은 실패할 수 있다. 배치된 생존 아군의 레벨·최대 HP·공격·방어·특공·특방·속도를 비교하며, 더 강하거나 빠른 적일수록 성공률이 낮아진다. 예비 디지몬·알·전투 불능 디지몬은 계산에서 제외한다. 같은 전력이면 첫 시도는 70%이며, 일반 전투에서는 최소 10%·최대 90%다. 재시도는 5%p씩 세 번까지 보정하고 확정 성공으로 바뀌지 않는다.

보스·최종 보스·라이벌(중간보스) 전투에서는 도망 버튼을 비활성화한다. 보스의 동료만 남은 상태도 전투가 끝날 때까지 도망할 수 없다. 호출 경로에서도 같은 제한을 검사하며 실패한 도망으로 처리해 적의 턴을 주지 않는다.

도망 실패는 아군의 도망 행동 이후 기존 적의 차례로 이어진다. 스테이지·보상·경험치가 증가하지 않고, 실패 횟수는 같은 전투에서만 보존된다. 성공은 경험치·아이템·승리 회복 없이 다음 스테이지로 이동한다. 스토리 전투에서는 기존 도주 결과로 돌아간다.

다음 스테이지로 넘어갈 때 살아 있는 적은 기존 교체와 같은 리콜 이펙트로 퇴장한다. 다음 적은 짧은 공백 후 같은 등장 이펙트로 나타난다. 적의 HP를 0으로 만들거나 사망 클립을 재생하지 않는다. 2대2에서 1대1로 줄어드는 아군도 리콜하며, 적의 등장까지 조작을 잠근다. 게임 속도 설정은 퇴장·등장·조작 잠금에 함께 적용한다. 실제 전투 불능은 기존 사망 처리를 유지한다.

`src/battle/escape.js`는 확률·제한, `src/three/switchPresentation.js`는 기존 교체 타이밍과 공통 큐 생성, `src/App.jsx`는 기존 전투 턴과 스테이지 이동을 연결한다. 렌더러의 사망 판정은 변경하지 않았다.

검증: `npm run test:escape` 및 `npm run test:items`, `npm run verify`, `npm run build`. 도망 성공·실패·보스 제한과 1×/2× 교체 타이밍은 실제 앱 핸들러를 포함한 회귀 테스트로 확인한다. 실제 3D 화면·저장·배포 패키지의 증거는 workspace maintenance/digilog-escape-2026-10-06에 보관한다.
