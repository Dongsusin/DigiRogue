# 명예의 전당

메인 메뉴의 명예의 전당에서 캐주얼과 하드의 공용 순위를 각각 10위까지 조회합니다. 플레이어 이름이나 이메일은 표시하지 않고 최종 멤버와 총 턴, 200층 클리어 날짜, 마지막 맵만 표시합니다. 디지몬에 마우스를 올리거나 키보드로 포커스하면 당시 레벨·체력·타입·속성·능력치·기술·장착 아이템 수량이 나옵니다.

## 기록 기준

- 새 모험부터 완료된 전투 라운드를 누적합니다. 2대2의 개별 명령이나 개별 타격은 따로 세지 않습니다. 아이템·교체·도망·이벤트 전투도 실제로 소비한 라운드를 반영합니다. 전투가 없는 이벤트, 진화와 교체 후보 선택은 추가 턴이 아닙니다.
- 캐주얼 또는 하드 200층의 본 전투를 승리한 뒤 최종 상태를 확정했을 때만 등록합니다. 공격 연출 중 적 HP가 0이 된 순간에는 등록하지 않습니다. 데일리와 무한 모드는 대상에서 제외합니다.
- 인증 UID마다 모드별 최소 턴 기록 한 개를 보관합니다. 같은 기록을 재전송하거나 이전 최종 저장을 이어도 중복되지 않습니다.
- 알을 포함한 보유 멤버 최대 8마리를 스냅샷으로 남깁니다. 지역 지원 동료는 제외합니다. 이후 아이템·진화·파티 변경은 이미 등록한 기록을 바꾸지 않습니다.
- 자동 저장과 선택 저장에 누적 턴을 보관합니다. 업데이트 이전 저장에는 전체 턴을 알 수 없으므로 이전 클리어를 임의의 점수로 등록하지 않습니다. 기존 게임의 이어하기는 유지합니다.
- 게스트는 기존 커뮤니티용 익명 Firebase UID를 재사용합니다. 명시적으로 새 Google 계정에 진행 기록을 가져올 때 명예의 전당 최고 기록도 새 UID로 다시 전송합니다.

## 네트워크와 보안

Firebase Realtime Database의 hallOfFame/{classic|hard}/entries/{uid}에 저장합니다. 기존 채팅과 접속 인원 규칙은 유지합니다. 실시간 순위 구독이나 주기적 폴링은 사용하지 않습니다. 창을 열거나 모드를 바꾸거나 새로고침할 때 totalTurns 인덱스로 상위 10개만 읽습니다. 개인 기록은 조건부 PUT과 ETag를 사용해 더 나쁜 기록으로 덮어쓰는 경쟁을 방지합니다. 쿼리 조회에는 ETag를 요청하지 않습니다.

서버 규칙은 소유 UID, 모드, 최종 층, 정수 턴, 서버 기록 시각, 최대 8멤버·8기술·80아이템과 필드 형식을 검사합니다. 외부 이미지 URL은 저장하지 않습니다. 게임의 로컬 에셋 목록으로 이미지를 찾습니다. 네트워크 실패 시 현재 프로필의 로컬 대기열에 모드별 최고 기록을 남기고 다음 접속·연결 복구·명예의 전당 열기에서 재시도합니다. 이전 전송의 응답이 같은 모험의 더 좋은 대기 기록을 지우지 않습니다.

실제 전투는 브라우저에서 실행되므로 서버 규칙만으로 변조된 플레이 결과를 증명하거나 차단하는 서버 판정 시스템은 아닙니다. 순위 데이터의 형식·소유권·최고 기록 갱신을 검증하는 범위입니다.

## 검증 및 반영

명예의 전당 모델·HTTP 동시 갱신 검사: npm run test:hall. 기존 전투·저장·인증 검사는 관련 test: 명령으로 실행합니다. 실제 RTDB 규칙 검사는 인증 에뮬레이터 127.0.0.1:9099와 데이터베이스 에뮬레이터 127.0.0.1:9000을 사용하고 FIREBASE_DATABASE_EMULATOR_HOST=127.0.0.1:9000에서 npm run test:hall:rules를 실행합니다. 개발 서버에서 운영 순위 등록은 차단하며, 로컬 검증에서는 VITE_COMMUNITY_EMULATOR=true를 사용합니다.

운영 반영 시 Firebase 프로젝트 digirogue-510313의 database.rules.json을 배포한 뒤 일반 웹 빌드·배포 절차를 따릅니다. 검증용 기록은 demo-digirouge 에뮬레이터에만 등록하며 운영 순위에 올리지 않습니다.
