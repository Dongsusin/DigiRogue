# 채팅과 현재 플레이 인원

게임은 Vercel의 정적 배포를 그대로 사용한다. 채팅과 접속 상태만 기존 Firebase 프로젝트의 Realtime Database로 연결하며 Vercel 함수, 외부 채팅 서비스, 주기적 HTTP 조회, heartbeat 쓰기를 추가하지 않는다.

- 메인: 접속 인원 + 접고 펼치는 전체 채팅. 전투: 전체 채팅만 표시.
- 인원: 현재 열린 게임의 인증 UID별 접속 여부. 같은 UID의 여러 탭은 한 명으로 계산한다. 숨겨진 탭과 오프라인 탭은 연결을 닫는다. 비정상 종료도 서버 onDisconnect로 정리한다.
- 메시지: 최근 40개를 고정 슬롯에 저장. 한 메시지 전송은 작은 head 조회와 원자적 PATCH(슬롯 1개·head·전송 시각)로 끝난다. 동시에 전송한 경우에만 최대 3회 시도한다.
- 수신: 인원 구독은 메인에서만, 메시지 구독은 채팅을 펼쳤을 때만. 같은 경로의 초기 스냅샷/자식 이벤트는 SDK의 동일 연결을 사용한다.
- 서버 규칙: 인증 필요, 200자, 이름 16자, UID별 4초 간격, 서버 시각, 순번 및 슬롯 검증. 메시지 삭제·임의 수정·UID 위조·쿨다운 초기화 금지.
- 게스트: 게임 로그인과 분리된 보조 Firebase Auth를 사용한다. 기존 게스트 저장 및 Google 동시 로그인 제한은 바꾸지 않는다. 공개 이름에는 Google 실명·이메일을 자동으로 사용하지 않는다.
- 네트워크 장애는 게임을 막지 않는다. 실패한 전송을 나중에 자동 게시하지 않는다. 채팅 입력의 Enter/Escape는 게임 명령으로 전파되지 않는다.

## 검증

일반 회귀 검사: npm run test:community

보안 통합 검사는 Firebase Auth(9099)·Database(9000) 에뮬레이터와 demo-digirouge 프로젝트에서 실행한다. FIREBASE_DATABASE_EMULATOR_HOST=127.0.0.1:9000 설정 후 node --test scripts/verify-community-rules.mjs를 실행한다. 운영 데이터에 대한 테스트 초기화는 허용하지 않는다. 테스트는 실제 배포 규칙을 읽어 전송 제한, 권한, 동시 쓰기, 40개 상한을 검증한다.

VITE_COMMUNITY_EMULATOR=true는 Vite 개발 모드에서만 로컬 Auth/DB로 연결한다. 프로덕션 빌드에는 에뮬레이터 연결이 활성화되지 않는다. Firebase 규칙 배포: firebase deploy --only database --project digirogue-510313

## 사용량 범위

Vercel에는 정적 파일의 최초 다운로드·업데이트 비용만 발생하며 채팅용 함수 호출은 없다. Firebase에는 활성 연결과 실제 수신·전송 트래픽이 발생한다. 채팅을 펼친 사용자 수와 대화량에 따라 달라지므로 비용이 0이라고 가정하지 않는다. 게임 에셋의 기존 영구 캐시와 Brotli 모델 배포는 유지한다.
